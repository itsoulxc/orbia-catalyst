A coding studio that runs on your own machine.

Catalyst plans, writes and tests software using models stored on your PC. Your prompts and your code stay there too.

Code blocks that can run, run. Catalyst opens them in a preview inside the conversation, so you see the result before you decide what to change.

    Fig. 1 Simulated session in Catalyst Studio, timings shortened. The game is real: put your pointer on it to take over.

    The model proposes. Catalyst decides.

    Every step a model wants to take arrives as a typed action. The runtime checks it against your policy, runs it inside set limits and records what happened.

    Reading a file goes straight through. Writing one waits for your approval. Reaching the network is refused unless you turn it on.

    server/policy.json
{
  "allow_network": false,
  "require_confirmation_for_writes": true,
  "require_confirmation_for_commands": true,
  "max_command_seconds": 120,
  "max_patch_bytes": 2000000
}

    Unplug the network cable. It keeps working.

    The interface talks to an engine on 127.0.0.1. The engine loads a GGUF file from your disk and runs it on your GPU or CPU. No account, no relay, no usage meter.

    Overload Guard
    Watches memory, VRAM and CPU so a long run does not stall the rest of your PC.
    Project memory
    Decisions and rules live in your workspace, where you can read and edit them.
    MCP
    Connect local tools through Model Context Protocol when a project needs them.
